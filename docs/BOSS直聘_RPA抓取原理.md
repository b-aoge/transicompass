# BOSS直聘 岗位数据 · 八爪鱼 RPA 抓取原理

> 用途：为「转型罗盘 TranSiCompass」的**岗位推荐功能**提供真实在招岗位的数据来源思路。
> 本文是方法论与接入设计，不含可直连生产环境的密钥；生产环境请在授权与个人研究范围内按合规边界执行。

## 1. 八爪鱼采集器的工作原理

八爪鱼（Octoparse / 深圳市数阔信息）是一款**零代码可视化网页采集 + RPA** 平台。一条采集任务的本质是"把人浏览网页的动作录下来，再自动重放"：

1. **打开目标网站**：在内置 Chrome 浏览器里输入目标 URL（或选用官方模板）。
2. **定义采集流程**：在页面上点选要抓的字段（标题、薪资、公司、链接…），并配置交互步骤——
   - 循环提取列表（`循环-提取数据`）
   - 翻页（`循环翻页` / 滚动加载 / 点击"下一页"）
   - 进入详情页（列表→详情两级抓取）
   - 登录态保持、表单提交、条件分支
3. **运行并导出**：本地调试或云采集（云端可定时、无人值守、IP 轮换）；结果导出为 CSV / Excel / JSON / 数据库 / API。

核心能力：智能识别列表与字段、代理 IP、验证码识别、自动重试、断点/增量采集、数据清洗（去重/格式化/正则）。

## 2. BOSS直聘 的反爬特征与八爪鱼应对

BOSS直聘 反爬严格，直接 `requests` 抓取几乎必封。常见特征与对应策略：

| 反爬特征 | 八爪鱼应对 |
|---|---|
| 必须登录才显示完整薪资/详情（游客隐藏字段） | 先"显示网页"手动登录，再返回继续采集；准备 2–3 个账号轮换，企业账号更稳 |
| 单 IP 高频必封 | 动态住宅代理 / 云节点 IP 轮换（付费代理高匿名，按流量计费） |
| 行为规律性被识别 | 加入随机延迟（约 2–5 秒），分时段采集，开启"浏览模式"让 UA 与浏览器指纹更真实 |
| 滑块 / 验证码 | 接入打码平台或人工过码；登录态保持减少触发 |
| 城市编码藏在 URL | 城市编码预查（如北京 `101010100`），搜索词做 URL 编码 |
| 风控上限 | 单关键词翻页一般只抓前 15 页，超出易触发风控 |

采集到的字段通常为：城市、岗位名、公司名、薪资范围、学历要求、经验要求、公司规模/融资、岗位描述/JD、技能要求、岗位链接、招聘者信息。

## 3. 接入本项目的方案（归一化 → 赛道映射 → 推荐）

岗位推荐功能要"每个赛道至少推荐 3 个"，数据源用八爪鱼定时采集的 BOSS直聘 导出即可：

1. **采集**：在八爪鱼建任务，按三条赛道关键词分别采集（如 `工商业储能`、`BIM`、`工程 出海`），导出 JSON/CSV。
2. **归一化**：把原始字段映射成本项目的 `OpenRole` 结构（见 `src/lib/jobs/openRoles.ts`）：
   岗位名、公司、城市、薪资、经验、来源、采集方式。
3. **赛道映射**：用 `knowledge.ts` 的 `keywords` 对每个岗位做关键词命中，归类到
   `NEW_ENERGY_STORAGE` / `SMART_CONSTRUCTION_BIM` / `ENGINEERING_B2B_OVERSEAS`。
4. **推荐兜底**：每个赛道取 ≥3 条；样本不足时用赛道知识库 `typical_roles` 补齐（标"待采集"），保证界面永远 ≥3。
5. **渲染**：结果页每个赛道卡片增加"真实在招岗位（采集样例）"区块。

> 注意：BOSS直聘 反爬强、需登录、部分字段游客不可见。采集频率务必克制，避免对平台造成压力。

## 4. 合规边界（必须遵守）

- 仅用于**个人研究 / 授权的市场分析**，不转售、不二次分发原始岗位数据。
- 遵守目标站点 `robots.txt` 与使用条款；部分招聘站点明确禁止爬取，须以最新条款为准。
- 控制频率与规模，不绕过付费墙、不窃取个人信息。
- 本项目结果页展示的岗位为**采集样例 / 脱敏数据**，生产环境由八爪鱼定时任务刷新，且不对岗位真实性做绝对化承诺。
