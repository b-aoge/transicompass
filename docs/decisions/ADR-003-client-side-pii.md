# ADR-003: 简历解析与 PII 脱敏全部在客户端完成，服务端不接收文件

- Status: Accepted (2026-08-03)
- Deciders: 高见远（架构师）
- Related: ADR-001, ADR-006, ADR-010

## Background

产品需处理用户简历原文，含姓名、手机、邮箱、身份证、具体公司名等 PII。监管（个保法、数据安全法）对敏感个人信息处理有最小化与明示同意要求。最稳健的合规结构是"原文字节流永不离开浏览器"，从根本上消除服务端泄密面与法律责任。

## Decision

所有简历文本的解析、字段抽取与脱敏（姓名/手机/邮箱/身份证/具体公司名 → 占位符 `[NAME]`/`[PHONE]`/`[EMAIL]`/`[ID]`/`[COMPANY]`）在浏览器内完成。服务端**不存在**任何接收 multipart/form-data 文件上传或原始简历文本的路由。服务端 `/diagnosis` 只接收已脱敏的结构化文本（`DiagnosisInput`）。

## Consequences

- 正面：PII 不出浏览器，合规风险面降到最低；服务端无需文件存储与病毒扫描；第 12 章 T2 可用"服务端无接收路径"静态+运行时断言结构性保证。
- 负面：依赖客户端 JS 执行脱敏，需在前端写严格的正则与兜底；若用户绕过前端直连 API 提交未脱敏文本，需在服务端做二次正则过滤（不依赖，仅兜底）。

## Alternatives Considered

- 服务端接收原文后脱敏：合规面更大，需加密存储与审计，MVP 阶段不必要。否决。
