# ADR-005: 诊断拆为两阶段调用以满足「10 秒内有内容」

- Status: Accepted (2026-08-03)
- Deciders: 高见远（架构师）
- Related: ADR-004

## Background

非功能需求要求诊断端到端 P95 < 30s，且超过 10s 必须有流式内容反馈（不可长时间白屏）。单次大模型调用若承担"能力抽取 + 赛道匹配 + 差距 + 路径 + 改写"全部任务，首 token 时间难以稳定压在 10s 内，且一次长生成失败成本高。

## Decision

将诊断拆为两阶段顺序调用，经 SSE 流式推送：
- 阶段一（≤ 8s）：用 `qwen-flash` 做能力抽取，先回传 `transferable_skills`（5–8 条），用户立即可见进展。
- 阶段二（≤ 18s）：用 `qwen3.7-plus` 做赛道匹配 + 差距 + 路径 + 改写，回传剩余字段。
总预算 < 30s，阶段一在 10s 内提供首屏内容，满足流式反馈要求。

## Consequences

- 正面：稳定满足 10s 内首内容；阶段解耦，单阶段失败可局部降级；用便宜快模型承担首屏降低时延与成本。
- 负面：两次调用增加总 token 与一次网络往返；需在前端协调 SSE 事件顺序与 loading 态。

## Alternatives Considered

- 单阶段长生成：首 token 不稳，难达 10s 门槛，失败复算成本高。否决。
